Skill 1 of 7 · Need

C# / .NET

LSports' core backend language. You don't know it yet — but you know Java, which is 80% of the battle. This page covers the 20% that's different.

Why LSports cares The TRADE360 feed engine — the code that ingests scout data, builds fixture state and pushes market updates to sportsbooks — is written in C#. Their backend job posts ask for C# alongside Kafka and databases. If you join a backend team, this is the language on your screen every day.

Coming from Java: what's the same

Almost everything structural. Classes, interfaces, inheritance, generics (List<Shot>), exceptions with try/catch, garbage collection, a virtual machine (the CLR is .NET's JVM), and a package manager (NuGet is Maven/pip). Naming style differs: C# uses PascalCase for methods and properties (GetFixture(), not getFixture()).

The four things Java didn't teach you

1. Properties — fields with built-in get/set

Java's private int x + getX()/setX() boilerplate collapses into one line:

public class Fixture
{
    public int FixtureId { get; set; }          // auto-property
    public string HomeTeam { get; init; }        // settable only at creation
    public bool IsLive => Status == "InPlay";    // computed, read-only
}

var f = new Fixture { FixtureId = 101, HomeTeam = "Barcelona" };
Console.WriteLine(f.FixtureId);   // reads like a field, runs like a getter

2. LINQ — SQL over your collections

The single biggest quality-of-life feature. Instead of loops, you chain queries. Read => as Java's -> lambda:

// total xG of big chances, best first
var bigChances = shots
    .Where(s => s.Xg > 0.3)
    .OrderByDescending(s => s.Xg)
    .ToList();

double totalXg = shots.Sum(s => s.Xg);
var byPlayer  = shots.GroupBy(s => s.Player)
                     .Select(g => new { Player = g.Key, Xg = g.Sum(s => s.Xg) });

Java's Streams API (shots.stream().filter(...).collect(...)) was inspired by LINQ — LINQ is just terser and everywhere.

3. async / await — non-blocking I/O as plain code

A feed server holds thousands of connections. Blocking a thread per connection doesn't scale; async/await frees the thread while I/O waits. Rule: an async method returns Task / Task<T>, and you await it.

public async Task<MatchState> GetSnapshotAsync(int fixtureId)
{
    var json = await httpClient.GetStringAsync($"/snapshot/{fixtureId}");
    return JsonSerializer.Deserialize<MatchState>(json);
}
// The thread is NOT blocked during the HTTP call — it serves other requests.

4. Records & value types

record gives you an immutable data class with value equality in one line — perfect for messages:

public record MarketUpdate(int FixtureId, int MsgSeq, string Market, double Price);

Also: C# has real value types (struct) — unlike Java where everything non-primitive lives on the heap. You mostly just need to know this exists.

JSON — the daily bread of a feed company

Built into the standard library, no Jackson/Gson dependency:

using System.Text.Json;

var msg  = JsonSerializer.Deserialize<MarketUpdate>(json);
var back = JsonSerializer.Serialize(msg);

Your 2–4 week plan

  1. Week 1: Install the .NET SDK (dotnet new console starts a project). Rewrite small exercises you'd find trivial in Java. Focus on LINQ daily — it must become reflex.
  2. Weeks 2–3: Port your own live-pipeline consumer to C#: connect to RabbitMQ with the RabbitMQ.Client NuGet package, deserialize your TRADE-style messages with System.Text.Json, rebuild MatchState. You already know the logic — you're only learning syntax.
  3. Week 4: Make it async end-to-end and add a couple of xUnit tests (their pytest).
Your interview line "I learned C# by porting my TRADE360-style pipeline consumer from Python — RabbitMQ client, JSON message contracts, state rebuild." That beats any course certificate, and it turns a weakness question into a tour of your best project.
